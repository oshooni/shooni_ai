# 신청하면 자동 메일 (노슈니 오토메일)

신청서가 들어오는 순간, 내가 자고 있어도 손님에게 확인 메일이 가고 나에게 알림이 온다.

```
손님 신청 → 수퍼베이스 테이블에 새 줄 → (초인종) → 구글 앱스 스크립트(메일 비서) → 내 지메일에서 발송
                                                                   ├ 신청자: 신청서 확인 메일
                                                                   └ 나: 새 신청 알림
```

비유로 설명하면 쉽다. 수퍼베이스 웹훅은 "초인종", 앱스 스크립트는 "메일 비서", HOOK_KEY 는 "초인종 암호"다. 사용자에게 설명할 때 이 비유를 쓰고 기술 용어는 괄호로만 붙인다.

## 이 스킬이 맞는 경우

- 신청·가입 데이터가 수퍼베이스 테이블에 쌓인다
- 메일을 하루 100명 이하로 보낸다 (개인 지메일 앱스 스크립트 무료 한도)
- 내 지메일 주소로 보내도 괜찮다

수퍼베이스가 없거나, 하루 100명을 자주 넘거나, hello@내도메인 주소가 꼭 필요하면 이 스킬 범위 밖이라고 먼저 말한다.

## 진행 순서

### 0. 먼저 확인할 네 가지

한 번에 하나씩 묻는다. 답을 이미 알 수 있으면(대화·파일·사용자가 준 주소) 묻지 않고 확인만 받는다.

1. 신청이 쌓이는 수퍼베이스 프로젝트와 테이블 이름
2. 그 테이블의 칸 이름 — 최소한 이름 칸과 이메일 칸 (Table Editor 화면을 보거나 사용자가 붙여준 내용으로 확인)
3. 신청서가 결제 전에 저장되는지, 결제 후에 저장되는지
4. 메일을 보낼 구글 계정 (가게 전용 지메일 권장)

3번이 중요하다. 결제 전에 저장되는 구조인데 "신청 완료"라고 보내면 결제 안 한 사람에게 틀린 안내가 나간다. 모르면 "접수"로 쓴다.

### 1. 메일 문장 만들기

`references/mail-writing.md` 를 읽고 따른다.

- 사용자의 신청 페이지 주소가 있으면 읽어서 일정·장소·준비물·다음 단계를 가져온다. 페이지에 없는 사실은 지어내지 않는다
- 신청자 메일 초안과 알림 메일 설명을 사용자에게 먼저 보여주고 확인받는다. 진짜 손님에게 사람 확인 없이 나가는 메일이라 이 확인은 건너뛰지 않는다

### 2. Code.gs 완성

`assets/Code.gs` 를 복사해서 채운다.

- CONFIG: shopName, table, fields.name, fields.email, notifyOwner, ownerEmail
- 신청자메일(r): 1단계에서 확인받은 문장. 신청 줄의 다른 칸을 쓰려면 `esc(r.칸이름)` 으로 넣는다 (손님이 입력한 값은 반드시 esc 로 감싼다)
- 나머지 코드와 맨 위 설치하기 함수의 위치는 바꾸지 않는다. 설치하기가 맨 위에 있어야 실행 메뉴에서 기본으로 잡힌다

완성한 Code.gs 를 파일로 사용자에게 준다.

### 3. 설치 — 사용자와 함께

`references/install-guide.md` 의 1~4단계를 순서대로 안내한다. 각 단계 끝의 "함정"을 미리 말해준다.

브라우저를 직접 다룰 수 있는 환경이면 클릭은 대신 해도 된다. 다만 아래 두 가지는 사용자가 직접 누르게 하고 멈춰서 기다린다.

- 구글 권한 허용 화면 (계정 권한을 주는 일)
- 수퍼베이스 SQL Editor 의 Run (운영 데이터베이스를 바꾸는 일)

4단계 SQL 은 `assets/supabase-trigger.sql` 에 테이블 이름, 웹 앱 주소, HOOK_KEY 를 채워서 준다. 트리거 이름은 `테이블이름_mail` 처럼 알아보기 쉽게 짓는다.

### 4. 시험

`references/install-guide.md` 5단계. 비서 주소를 먼저 시험해 `{"applicant":"sent","owner":"sent"}` 를 확인하고, 그다음 실제 신청 페이지에서 사용자 본인 이메일로 시험 신청을 하게 한다. 시험 신청 줄은 사용자가 직접 지우게 안내한다.

### 5. 마무리 안내

끝나면 짧게 정리해 준다.

- 이제 무엇이 자동으로 일어나는지 (신청자 메일, 알림 메일 각각 한 줄)
- 문장을 고치는 법: 고친 뒤 "배포 관리 → 수정 → 새 버전" ("새 배포"는 주소가 바뀌어 연결이 끊김)
- 끄는 법: drop trigger SQL 또는 Webhooks 목록에서 삭제
- 한도: 하루 100명

## 하지 않는 것

- 광고 문구(할인, 신상품 추천)를 확인 메일에 섞지 않는다. 광고 메일은 수신 동의·(광고) 표기가 필요한 별개의 일이다
- 손님 메일을 사용자 확인 없이 바꿔 배포하지 않는다
- HOOK_KEY 나 service_role 같은 열쇠를 공개 저장소·화면 코드·대화 기록에 남기지 말라고 안내한다. HOOK_KEY 는 앱스 스크립트 스크립트 속성과 수퍼베이스 트리거에만 있으면 된다
