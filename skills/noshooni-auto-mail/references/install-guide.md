# 설치 가이드 — 사용자에게 그대로 보여줄 단계

사용자가 직접 따라 할 화면 순서. 사용자에게 안내할 때는 이 순서를 바꾸지 않는다. 각 단계 끝의 "함정"은 실제로 막혔던 지점이라 꼭 같이 알려준다.

## 1단계. 앱스 스크립트 프로젝트 만들기

1. 메일을 보낼 구글 계정으로 로그인한 크롬에서 script.google.com/home/projects/create 를 연다
2. 편집 창의 `function myFunction() { }` 를 전부 지운다
3. 완성한 Code.gs 전체를 붙여넣고 저장(Cmd+S / Ctrl+S)

함정: 가게 전용 지메일을 따로 쓰는 걸 권한다. 개인 메일로 보내면 손님에게 개인 주소가 보이고 답장이 섞인다.

## 2단계. 설치하기 실행 + 권한 허용

1. 위쪽 실행 버튼 옆 함수 선택 칸이 "설치하기"인지 확인 → ▶ 실행
2. "승인 필요" → 권한 검토 → 계정 선택
3. "Google에서 확인하지 않은 앱" 경고 → 왼쪽 아래 "고급" → "(프로젝트 이름)(으)로 이동"
   - 내 계정 안에서 내가 만든 코드라서 뜨는 경고다. 개발자 칸에 본인 이메일이 적혀 있는지 같이 확인시킨다
4. 권한 목록에서 "모두 선택" 체크 → 계속/허용
5. 실행 로그에 `HOOK_KEY=...` 가 찍히고, 메일함에 미리보기 두 통(신청자용, 알림용)이 오면 성공

함정 1: 함수 선택 칸이 다른 함수로 잡혀 있으면 엉뚱한 함수가 실행되고 권한만 반쯤 받는다. 설치하기가 파일 맨 위에 있으면 기본으로 잡힌다. 그래도 안 바뀌면 페이지를 새로고침한다.
함정 2: 요즘 구글 허용 화면은 권한마다 체크박스가 있다. "Gmail에서 이메일 보내기"를 빼먹으면 로그에 "does not have permission ... mail.google.com" 오류가 난다. 설치하기를 다시 실행하면 허용 창이 다시 뜨니(requireAllScopes) 이번엔 모두 선택.

## 3단계. 웹 앱으로 배포 (비서에게 주소 만들기)

1. 오른쪽 위 배포 → 새 배포
2. 유형 선택 톱니 → 웹 앱
3. 다음 사용자 인증 정보로 실행: 나
4. 액세스 권한이 있는 사용자: 모든 사용자
5. 배포 → 웹 앱 URL(https://script.google.com/macros/s/…/exec) 복사

"모든 사용자"가 필요한 이유: 수퍼베이스가 로그인 없이 초인종을 눌러야 해서. 대신 2단계에서 만든 HOOK_KEY 암호가 문지기 역할을 해서, 암호 없는 요청은 아무 메일도 못 보낸다.

## 4단계. 수퍼베이스에 초인종 달기

1. 수퍼베이스 → 해당 프로젝트 → Integrations → Database Webhooks → 처음이면 Install integration (pg_net 확장 사용)
2. SQL Editor → assets/supabase-trigger.sql 에서 테이블 이름, 웹 앱 주소, HOOK_KEY 를 채운 SQL 붙여넣기 → Run
3. "Success. No rows returned" 가 나오면 끝. Integrations → Database Webhooks → Webhooks 목록에도 보인다

함정: 암호는 HTTP Headers 가 아니라 HTTP Parameters(주소 뒤 ?key=)로 보내야 한다. 앱스 스크립트는 요청 헤더를 읽지 못한다. 위 SQL 의 네 번째 칸이 그 자리다.
Webhooks 화면에서 직접 만들 때도 같다: Table, Events=Insert 하나만, HTTP Request/POST, URL=웹 앱 주소, HTTP Parameters 에 key=암호.

## 5단계. 시험

먼저 비서 주소만 시험한다 (실제 테이블은 건드리지 않음). 터미널:

```bash
curl -L -X POST "웹앱주소?key=암호" \
  -H "Content-Type: text/plain" \
  -d '{"type":"INSERT","table":"테이블이름","record":{"name":"시험","email":"내메일@gmail.com"}}'
```

`{"applicant":"sent","owner":"sent"}` 가 나오고 메일 두 통이 오면 비서는 정상.
그다음 실제 신청 페이지에서 내 이메일로 시험 신청을 한 번 한다. 그 시험 줄은 나중에 테이블에서 직접 지운다.

## 운영 중 알아둘 것

- 메일 문장을 고친 뒤에는 배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포. "새 배포"를 누르면 주소가 바뀌어 수퍼베이스 연결이 끊긴다
- 수퍼베이스 웹훅 기록에 302 가 보여도 정상이다. 앱스 스크립트는 원래 302로 대답한다
- 개인 지메일은 하루 수신자 100명까지. 넘으면 다음 날 회복된다. 자주 넘으면 내 도메인 메일 서비스(Resend 등)로 갈아탈 시점
- 끄기: SQL `drop trigger if exists "트리거이름" on public.테이블이름;` 또는 Webhooks 목록에서 삭제
- 무슨 일이 있었는지 보려면 앱스 스크립트 왼쪽 ≡(실행) 메뉴. 언제 실행됐고 어떤 오류가 났는지 다 남아 있다

## 막힐 때 보는 표

| 증상 | 원인 | 해결 |
|---|---|---|
| 미리보기 메일이 안 옴, 로그에 permission 오류 | Gmail 권한 체크 빠짐 | 설치하기 다시 실행 → 모두 선택 |
| 실행했는데 로그에 HOOK_KEY 가 없음 | 다른 함수가 실행됨 | 함수 선택 칸을 설치하기로, 안 되면 새로고침 |
| 신청해도 메일이 안 옴 | 암호를 Headers 에 넣음 / 암호 오타 | HTTP Parameters 의 key 확인 |
| 문장을 고쳤는데 예전 문장이 감 | 새 버전으로 배포 안 함 | 배포 관리 → 수정 → 새 버전 |
| 신청자 메일만 안 옴 | 이메일 칸 이름이 다름 | CONFIG.fields.email 을 실제 칸 이름으로 |
| 스팸함으로 감 | 새 지메일이라 신뢰가 낮음 | 처음 며칠은 내 메일로 주고받기, 링크는 하나만 |
| "서비스 사용 한도 초과" | 하루 100명 넘음 | 다음 날 자동 회복 |
